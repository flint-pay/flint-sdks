# Pinned SDK inputs

`openapi.json` is the complete, unmodified public versioned API snapshot at Flint `32572092a05bcf71bedd57326f8eb75add6bd755` on `main`, copied byte for byte from the path recorded in `../sdk.lock.json`. Its SHA-256 is recorded in the lock; no contract values were changed. The API date is `2026-09-07`. All 710 source operations are retained. The packages select 709 operations, including the five form-encoded CLI/OAuth operations. `authorizePartnerInstall` is a browser consent redirect and remains excluded; handwritten partner OAuth helpers build its URL. The inventory test checks every selected operation and explicit exclusion.

The profiles and synthetic HTTP/model cases originated in `flint-pay/sdk-generator` revision `314de2ee5975e3a5cc7cf385babd23b84eb489fa`, `tests/providers/flint/`. Historical provenance is retained independently of this source pin. Generator `7713b37e9bcdf63dbb6242e33c5c5ca4bbd8d323` supports the callback and negative query constructs. The checked-in packages now represent the complete selected candidate. Package version `8.0.0` is release preparation, not a production pin. Keep this PR a DO NOT MERGE draft; after production deploys the contract, re-pin to that deployed SHA and regenerate before release.

The common profile uses path-derived operation names and positional path IDs with flat params for every method, including union request bodies. It removes deprecated aliases. Integer counters use native numbers; integers inside `Money` remain exact strings. Scalar query values are accepted where the API takes an array. Error fields are read from the API's `error` object, and `IDEMPOTENCY_KEY_IN_PROGRESS` identifies a pending outcome. `../scripts/profiles.mjs` derives retries and idempotency settings from each operation's idempotency class. Optional-key writes get an SDK-minted `flint-sdk-` key reused across retries, required-key writes need the caller's saved key, and operations without a key header send none. GETs and keyed writes make up to 3 attempts; the generated `RUNTIME.md` describes the retry and outcome rules.

The five authentication profiles use complete alternatives from the pinned contract. Checkout uses bearer `checkoutToken`; the `apiKey` shortcut uses merchant bearer authentication. The contract does not declare `ApiKeyHeader`, so there is no `merchantKey` profile. Partner app operations no longer accept onboarding sessions. `../tests/provenance.json` preserves historical fixture and migration evidence separately from the current full-spec pin and method bindings. Namespaces now follow API paths, including `sandboxes`, `authContext`, `apiRequestLogs`, `resourceTimelines` and `partnerApps`; old cross-resource bindings and deprecated aliases are removed. Inventory lifecycle calls retain their `transition` methods with explicit `action` params.

The common profile's `overrides` are existing provider corrections and representation settings, applied before reference resolution:

- Integer bounds of `2^63-1` on uint64/int64 inventory and error-detail fields are not safe integers. Each field is declared `int64` without the bound. The native-number profile enforces the safe integer range for counters at runtime.
- Metadata `propertyNames` reject keys starting with `flint_` through `not`. They use the equivalent lookahead-free pattern instead.
- Partner app credential branches forbid the other credential fields with `not: {}` schemas. They use `not` with `required` instead.
- `DeliveryEligibilityExpression` and `DeliveryZoneConfiguration`, and their `Input` request forms, select one operator through recursive `$ref` alternatives that TypeScript can't type. Each alternative is replaced by its single required key; the closed parent keeps exactly one operator per node.

`../tests/full-http-cases.json` and `full-model-cases.json` are synthetic regression cases, not live transaction certification. The eight historical checkout-specific delivery cases now exercise the replacement delivery quote/selection endpoints with the same buyer/merchant and missing-credential coverage. The method inventory follows the current API paths; payment fixtures include required nullable refund deadlines and Elements payment options. `full-inventory.json` records the pinned export's inventory. Do not add private provider definitions or real request/response data.

To update the API, obtain the matching versioned public JSON export, record its exact upstream revision and SHA-256 in `sdk.lock.json`, and keep the version header consistent. Review authentication bindings, operation inventory, examples, overrides and fixture expectations together. To update the generator, pin its exact revision, run `npm run setup`, regenerate, and review the complete diff before release.
